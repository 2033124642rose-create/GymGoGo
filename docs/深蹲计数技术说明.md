# 第三阶段：真实深蹲计数与基础战斗

2026-10-28：第二阶段已由用户真人验收并本地提交 `05f418b`。第三阶段代码与自动验证完成，**真实深蹲效果、误计数表现和声音听感尚待用户真人验收**，第三阶段未最终提交。没有 AI API、视频上传或录像。

## 从关键点到一次攻击

本地摄像头 → MediaPipe Lite → 图像关键点 + worldLandmarks + 采集时间戳 → SquatCounter → 有效完成事件 → App 本局计数 → 一次扣血、一次短音效 → 10 次后通关。

图像关键点用于关节可见性、站位与髋部下降；世界关键点用于三维膝角，避免用显示区域的二维角度替代动作数据。世界坐标也是模型估计，不是硬件深度测量。没有完整关键点时暂停，不拿缺失值猜测动作。

预览仍按比例显示完整画面；实际输入继续读取 videoWidth / videoHeight，捕获宽度最多 640px。显示框、大屏、CSS 缩放不参与计数角度或采集尺寸计算。

## 状态机

`先站直校准 → 站立就绪 → 下蹲中 → 底部确认 → 起立中 → 站直确认 → +1`

- 初次蹲着入镜后站起不算一次；必须先确认站立基线。
- 双膝均达到下蹲条件，且髋部相对基线下降并稳定保持，才进入底部状态。
- 只有完整站起并稳定确认后输出一次事件；蹲着停留、底部弹跳或未站直不连续加数。
- 遮挡、低可见度、出框、缺少三维数据、明显移步、帧间断或动作超时会取消未完成动作；已完成次数保留，重新站直确认后才能继续。
- 计数器满 10 次不再输出事件；App 也限制单局计数并核对 real / demo 来源和事件序号，避免重复攻击。

## 首版参数（产品工程假设，不是医学标准）

集中位于 `src/squat/SquatCounter.ts` 的 `SQUAT_RULES`，尚未用本项目真人样本定标。

| 规则 | 当前值 / 条件 |
| --- | --- |
| 关节质量 | 双肩、髋、膝、踝 visibility ≥ 0.65，位于画面内部 |
| 站直 / 离开站立 | 双膝角至少 160°；任一膝低于 145°进入下降阶段 |
| 下蹲确认 | 双膝均不高于 110°，左右角差不超过 30°，髋部图像下降至少基线躯干高度的 18% |
| 站立基线 | 持续至少 500ms，至少 4 个有效样本 |
| 底部 / 回站确认 | 底部至少 160ms / 3 帧，回站至少 250ms / 3 帧；同时检查髋部回到基线附近 |
| 时序与平滑 | 最近 3 个有效样本的中值；最短动作 800ms、最长 15s；相邻有效帧间隔超过 700ms 则重新确认站立 |
| 站位变化 | 脚踝相对初始站位漂移或躯干尺度变化过大，取消当前动作并重校准 |

这些规则优先避免误加数，可能在光线差、关节遮挡、低帧率、特定角度或个体差异下漏计。坐下起立等相似运动仍可能混淆，未声称能识别所有动作。不存在已验证的准确率，不评估医学或精准姿势正确性。

## 模式、计时与反馈

- 默认“真实深蹲”：主动开启摄像头、主要关节识别成功后，“开始真实挑战”可点击。开始后先站直；此模式不提供手动加一次按钮。
- “按钮演示”：不要求摄像头，手动点击一次才加一次；真实姿态不驱动模拟次数。
- 切换模式清空本局；退出大屏不重置计数。真实模式关闭摄像头会暂停未完成动作，重开后需要站直，已完成次数保留。
- 开始前捕获、却在开始后才返回的旧帧被忽略。重置或通关后，继续到达的帧不能继续扣血。
- 本局用时为开始后的实际经过时间，包含站位调整 / 暂停识别时间，不等同于净运动时长。
- 每次有效动作触发既有怪兽受击、伤痕、扣血、计数放大及约 120ms 本地合成攻击音；10 次仅一次通关横幅、彩纸与短和弦。音效被浏览器限制时，计数和视觉仍工作，可点击“试听攻击音”或静音。
- 高级语音、复杂角色动画和更多特效不在本轮范围，UX-002 / UX-003 保留后续迭代。

## 自动验证与实际边界

74 项测试通过，保留第二阶段 49 项，新增：14 项纯状态机、8 项关键点到战斗整合、3 项基础音效。完整动作、10 次上限、半蹲、静止、单腿弯曲、缺少髋部下降、底部停留、未站直弹跳、单帧跳点、旧时间戳、低可见度、丢失、移步、长间断、过快 / 超时及重置均有覆盖。

整合测试用合成关键点和模拟 Worker，确认真实模式没有伪造按钮、一次事件对应一次计数 / 伤痕 / 音效、10 次只通关一次、摄像头关闭恢复、音效不可用不阻断计数、切换模式隔离。**合成序列不是真人录像，不能替代真人动作准确性验证。**

真实浏览器已验证模型仍以 GPU 初始化，对程序生成空白帧输出 `landmarks: []`、`worldLandmarks: []` 和采集时间戳；此测试未使用摄像头，也不证明真人深蹲已通过。当时页面默认真实模式、无摄像头时不能开始（已由下文 UX-004 准备流程替代）；按钮演示通关已回归。所有截图均不包含真实摄像头画面。

## 用户真人验收：先少量测试，再完整一局

1. 刷新 `http://127.0.0.1:5173/`，选“真实深蹲”，主动开启摄像头，再进入“战斗大屏”，点击“准备挑战”后走远就位。
2. 全身入镜站直稳定约 2 秒，等待大数字 3、2、1 结束；正式开局后显示“准备下蹲”。可先点“试听攻击音”确认音量。
3. 先做 3 个自然完整动作，观察“下蹲中 → 已到位，请站起 → 起立中 → 计数 +1”。应为 3 / 10、70 HP，每次完成只有一次攻击，不在蹲下瞬间加数。
4. 再做下面误计数检查。若正常，重置后做 10 次，确认只通关一次；继续动作不能把计数加到 11。

| 检查场景 | 预期 |
| --- | --- |
| 站着不动、只摆动手臂 | 不增加次数 |
| 只做浅幅弯膝后回站 | 不计完整动作 |
| 蹲下停留、底部小幅弹跳 | 未站直前不加数，不重复攻击 |
| 初次蹲着入镜再站起 | 不凭起立补一次，需先站立基线 |
| 进行到一半离开 / 遮挡 / 关闭摄像头 | 取消这次未完成动作，完成次数保持 |
| 重新入镜或重开摄像头 | 重新站直确认，再开始下一次完整动作 |
| 重置、切换模式、退出大屏 | 重置 / 切换清空；退出大屏保持，真实流不重启 |
| 关闭战斗音效 | 计数、扣血和通关正常，只是不播放攻击音 |

请记录“实际做了几次 / 网页显示几次 / 漏计或误计时大字停在哪个阶段”。不需要发送原始视频。若持续卡在站直、下蹲或起立阶段，反馈提示原文，由 Codex 检查并调整规则，不把失败掩盖成成功。用户确认前不创建第三阶段最终提交，不进入下一阶段。

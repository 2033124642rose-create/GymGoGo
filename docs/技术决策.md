## 2026-10-27 · 第一阶段首页交互原型

- 正式产品名称统一为 **GymGoGo**；目录保持 `D:\gymgogogo`。
- 实际安装：React / React DOM `19.3.1`、TypeScript `5.9.3`、Vite `7.3.7`、React 插件 `5.2.0`、Lucide React `0.468.0`；精确依赖树保存于锁文件。使用当前 Node.js `22.14.0` 完成构建。
- 暂定视觉方向：深紫冒险竞技场、薄荷绿怪兽、荧光绿行动按钮。该方案是供验收的初稿，尚未确认最终风格。
- 怪兽使用内联 SVG，场景和动效使用 CSS，图标使用 Lucide；无外部图片和字体请求，无额外素材 API 成本。
- 使用 React 状态 `idle / active / won` 管理演示；目标 10 次、每次伤害 10，怪兽生命值由计数派生，避免两个状态不一致。计时依据时间差计算，通关停止，重新挑战归零。

- 保持前端单项目，不提前建立后端和账号系统。开发服务绑定 `127.0.0.1:5173` 并启用严格端口，方便本机验收。
- npm 缓存放在项目的 `.npm-cache/` 并忽略，避免默认缓存目录写权限问题；不修改全局 npm 配置。

## 2026-10-28 · UX-001 大屏与可听状态

- 使用同一 DOM 组件切换固定视口布局，不移动 / 重挂载视频或识别器。ResizeObserver 测量剩余空间，再根据真实视频比例算 contain 尺寸，骨骼与视频共用显示矩形。状态和工具放在画面外，不遮挡头脚。
- 默认页面大屏不申请浏览器全屏权限，另提供系统全屏增强；监听 fullscreenchange 处理原生 Esc、权限拒绝与延迟许可。背景 inert、滚动锁、焦点恢复及页面 Esc 只影响显示，不停止摄像头。
- 声音属于展示层，不改 MediaPipe 或可见性判断。StableStatusAnnouncer 在原稳定识别状态上追加 1.2s 稳定时间和 4.5s 提示间隔，清理待播计时器避免关闭后播报。
- 仅使用 localService 的中文 SpeechSynthesisVoice；没有本地中文声线则使用 Web Audio 双提示音，无远程 TTS。试听明确不代表识别结果，自动播放受限时显示说明并允许重试 / 静音。
- 参考 [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) 与 [本地语音标记](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)；兼容行为以当前自动测试和实际浏览器结果为证，未宣称所有浏览器通过。

## 2026-10-28 · 独立的开局状态机（UX-004）

真实开局使用 ReadyGate 明确管理 idle / waiting / countdown / active / ended，按钮演示沿用原交互。人体测量复用 SquatCounter 的可信关节与三维膝角计算，深蹲计数规则未改。稳定准备使用双膝 >=160°、2 秒、至少 6 帧，并限制髋部漂移 0.12 倍躯干高度和脚部漂移 0.15 倍；相对坐标不依赖预览大小。阈值为待真人验证的产品参数。

使用采集时间戳推进倒计时，而非一个脱离识别状态的 setTimeout；帧间隔 >700ms、200ms 看门狗发现断流或页面隐藏时清空准备。过期 / 倒序帧不能推进旧局，状态切换同步写入 ref，避免 React 渲染批处理导致重复开局。

倒计时结束重置计数器，用最近 1000ms 已验证的站立帧校准，再把正式开局帧时间戳设为边界。准备帧永不生成攻击，第一组正式完整动作可以直接计数。用户手势时解锁本地 AudioContext，只在数字变化或开局时短鸣，受“战斗音效”开关控制；浏览器阻止音频不阻断视觉倒计时和计数。

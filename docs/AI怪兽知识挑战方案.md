# AI 怪兽知识挑战 · 技术与费用控制方案（待确认）

日期：2026-10-29。基线：本地已验收三关提交 5d4aec1；本轮仅方案，不实现、不提交、不部署、不调用真实模型。该功能独立于尚未开发的 P1 团队战报。

## 最终产品规则

每位玩家、每关、每次本关挑战只回答一道动态生成题。个人深蹲达标后立即锁住计数，进入知识挑战；答对才算个人本关任务完成、移出队列。只有全员深蹲达标且答对，才发徽章、通关和解锁。答错使本关失败，其他关已获得的奖励保留。问答无倒计时；走近键盘不产生新次数。模型故障与 uncertain 均不判负、不奖励、不解锁。

不使用人工预设题库或本地题目假冒 AI；自动化中的固定模型响应仅测试夹具，不进入产品。原纯运动派对与单人仍可使用；本地新建派对时明确选择 AI 知识挑战，能力不可用就不能静默绕过问答继续这场挑战。公网在预算控制获批准前不提供该模式。

1. PartySession：新增知识阶段、玩家本关答题状态、levelAttemptId、一次性结果收据；ReadyGate/SquatCounter/CameraController/AR 算法不改。
2. PartyGame 与独立 PartyQuiz 面板：出题状态、输入、判题、uncertain/失败恢复；失败使用现有怪物放大动画，尊重减少动态效果设置，提供键盘焦点与返回出口。
3. 新 server/quiz 服务：两个动作端点、结构校验、服务端回合登记、题目私有存储、去重/预算账本。旧 /api/review 行为不变；可抽取小型百炼传输助手，但不重构整套已验收战报。
4. 本地先使用串行写入、原子替换的私有状态文件，并禁止并发服务实例写同一文件；开发时新增忽略目录。存储失败或状态损坏时关闭 AI，不能换个ID重出题。抽象 store 接口，公网批准后再换持久事务存储，不引入账号或复杂业务数据库。
5. 浏览器仅存派对恢复凭据及必要界面快照，服务端保存题目、参考答案、判定、预算及必要回合检查点；不存视频、人体点或朋友实名。刷新恢复后摄像头不自动开启、基线重建、半次动作清除。凭据丢失/服务端记录过期必须明确终止或重建派对，不能假装恢复原题。

## 两次调用与数据边界

### 第一次：出题

服务端创建的 partyId + levelId + levelAttemptId + playerId 是唯一回合键；跳过/休息/再次准备不改变键。客户端提交服务端回合凭据，不允许自行指定模型、提示词、参考答案或任意下一关。服务端检查轮次、生成状态和额度后，先持久化 pending 及费用预留，再请求模型。

模型返回 JSON：question、referenceAnswer、keyPoints、explanation、topic、difficulty、answerability（明确/有歧义）。问题建议不超过60个中文字符、答案核心点1–2项、解释不超过100字；第一关直接常识、第二关简单情境、第三关基础原理，均不升级到专业医疗。主题类别是范围限制，不是题库。向模型提供本场已出题的短摘要，服务端检查规范化重复；重复或有歧义的输出不展示、不判负，允许预算内主动重试。无法保证语义绝不重复，已发布的问题不再更换。

服务端保存参考答案与解释；浏览器只收到 questionId、题干和阶段，出题解释也不得泄漏答案。不输出原始模型文本或隐藏参考答案到浏览器、日志、源码、localStorage。

### 第二次：语义判题及怪兽反馈

客户端仅提交 questionId、短答案、submissionId；服务端读取原题与参考答案，不能相信客户端提供的参考答案。答案建议最多120个中文字符，整个请求最多2KB；空白/超长先本地和服务端校验，不调用模型。模型返回 verdict=correct|incorrect|uncertain、explanation、monsterReaction；可增加内部 evidence 字段核对玩家哪些核心含义已表达，不依赖模型自报置信度数字。

系统规则要求接受同义、口语、短答与合理更准确的答案；题意多解、参考答案可疑、核心证据不足必须 uncertain。不能因为与参考文字不同就判错。判题温度低，出题温度适中；怪兽吐槽在同一次判题生成，不另花第三次调用。反应缺失/不合适而判题合法时，用明确的本地短反馈代替，不追加调用、不改 verdict。correct 后才展示怪兽认输；incorrect 才播放全屏占领与失败；解释和原答案可在已结束的本关复盘展示，不能提前泄漏给同题重试玩家。

输入以独立 JSON 数据提交给模型，系统明确禁止执行答案中的指令；拒绝工具、外链、任意系统提示覆盖，输出使用枚举与长度/内容校验、纯文本渲染。不能声称提示词注入可被完全消除；操纵性或无法评价的回答进入 uncertain，结合服务端回合校验与预算限制控制影响。规则校验不靠关键词判玩家答案正确与否。

百炼 JSON Object 仅保证合法 JSON，不保证字段和值正确，仍必须服务端校验；若现有模型/地域验证支持严格 Schema 可采用，不为此擅自换更贵模型。模型及地域沿用本地安全配置，实施阶段才在用户授权的调用额度内实测兼容性。

## 状态机与重复请求

active → quizGenerating → quizAnswering → quizJudging → quizCorrect / quizUncertain / levelFailed。

quizCorrect → 下一位 ready；若全员完成则 levelWon 或最终 won。出题/判题网络错误进入 quizUnavailable，可重试同操作或安全退出；不是 incorrect。quizUncertain 保留同一道题，允许明确主动重新判题或修改答案再提交（计入新的有限判题尝试），不允许点击随机换题。

- 每个回合最多一题成功发布；pending 由服务端唯一记录/锁保护，重复请求复用进行中状态或已保存结果。
- 同一 submissionId + 相同答案复用同一判定；同ID不同答案拒绝冲突。correct/incorrect 终态不能重复付费翻判，结果收据只消费一次。
- uncertain 后主动复判使用新的 submissionId，仍用原题。建议每题最多3次模型判题；额度用尽保留无法确定、只允许安全退出，绝不自动判负/过关。
- 结果包含 party/level/attempt/player/question/submission 标识；换人、重试、退出后迟到响应不可修改当前状态。操作状态先同步锁定，再渲染动画。
- 网络超时不代表供应商没有计费。pending 中断先查询本地保存结果；无法确认是否已调用则标记 interrupted，不自动重发。用户明确重试可能新增一次计费，先预留预算并提示。不承诺跨供应商的绝对“恰好调用一次”。
- 问答可休息，保留题目/输入/响应；后台请求完成只保存结果，恢复后再应用一次。跳过在运动阶段按原队尾规则；已达标但未答题的玩家若选择延后，保留原题到队尾、之后只答题，不再做零目标计数。全员延后仍暂停。不得借跳过标记答对。

## Boss 归零、失败与重试

HP=max(0,N×目标×10−本关有效次数×10)。运动最后一次依旧扣10HP并播放攻击，但HP0仅“体力耗尽，知识对决尚未结束”；不播放死亡/胜利、不给奖励。显示已答对人数与剩余知识回合，让玩家理解0HP为何尚未通关。全部答对才正式击败。

incorrect 立即冻结计数、队列和请求结果，进入 levelFailed，仅一次失败动画。重新挑战本关是显式新 levelAttemptId：本关全员次数/题目状态/HP/队列重置，所有玩家重新完成本关；前关计数/已得徽章保留。新挑战每人可生成新一道题，属于新费用，不是刷新重抽题；必须再次检查预算。

失败尝试的真实运动单独计入“历史尝试动作”，当前通关贡献只统计最终成功尝试；避免清空实际运动事实或把重试次数重复拿来扣新Boss血。最终结算区分成功路线与失败尝试，不增加健康/卡路里推断。返回派对结束本次闯关，回到本地队伍设置，保留昵称/帽子供确认，不隐式再开一局或把失败当通关。

AI 异常时可重试或退出这场知识挑战，保存未通关摘要；若想纯运动，明确重新创建纯运动派对，不把 AI 不可用当答对。此为兼容旧玩法，不是预设题替代。

## 公平性与可能错误

单次模型出题加单次模型判题无法保证知识完全正确或判题绝对公平；两次均来自同模型也不等于独立事实核验。本批不建设检索/医学知识库，不承诺零误判。采用窄主题、低歧义问题、生成时明确可答性、宽容语义判定、对矛盾结果转 uncertain、同答案缓存稳定结果、失败前展示简短理由及本地复盘。

常见错误：题目有争议/缺条件、参考答案错误、短答被误解、否定词混淆、注入诱导、JSON损坏/截断、403模型权限、429/超时、重复响应/旧玩家响应、预算/存储异常。前四项仅靠字符串校验无法完全发现，真人测试需覆盖；服务异常不判负。明显 incorrect 仍按产品规则失败，后续若要申诉复核须单独定义，不能暗中多次调用到答对为止。

## 费用控制方案（待确认的初始值）

正常每人每关2次模型调用；无重试完整三关=6N次，即2人12次、6人36次。不增加AI怪兽第三次调用，不自动生成团队战报。失败重开、uncertain复判、无效出题和超时重发都额外消耗，不能写成整场永远只有36次。

本地先关闭默认开关，由主持明确启用并看到上限。建议每个本关挑战总模型尝试最多5N次（每回合最多2次出题尝试、3次判题；中断后主动重试也占用这些次数）、每派对总100次、全服务当日100次、每分钟6次、同派对并发1次。正常6人36次可覆盖，但不能保证任意多次重试完成；额度到达就安全暂停。数字为待确认配置，不是已执行结果或费用承诺。

建议出题max_tokens=400、判题max_tokens=300，单次上游超时先12秒（可配置）、不自动重试；固定短系统模板与有界历史，服务端按实际模型分词/保守字节界限限制总输入，不把字符数当精确token数。无思考调用仅在模型支持时开启，防止隐藏推理预算失控。

计数与金额账本在上游调用前原子扣预留，拒绝并发穿透；失败/超时不擅自返还额度，日界限按Asia/Shanghai固定。金额预算使用实际选用模型及地域当前价格、严格输入/输出上限计算最坏成本并向上预留；价格配置未知或过期则关闭，而非猜测单次人民币费用。账本存储不可用时不调用。独立项目Key、提供方支持的硬配额/禁超额设置可作为补充；余额提醒、免费额度、IP限制、CORS、前端按钮和云函数Map都不是全局费用硬上限。现有单人战报若与问答共享Key并启用，也必须纳入总账本或单独限定，不能漏算。

公网现状：Cloudflare Pages可承载前端，Functions可做接口，但现有/publicMode关闭的战报不等于能用问答。Node本地文件方案不能直接部署为云端全局账本。后续可用独立Worker中的SQLite Durable Object提供串行额度预留、回合/题目持久记录，Pages绑定调用；对象按全局项目预算集中扣额，不能每派对各有一份“全局额度”。先事务预留再外部请求，不在存储事务内等待模型；另记pending并恢复。Free有额度限制，部署前核对账号资格，不升级付费。

只有服务器发行的主持邀请/会话额度可创建AI派对，限制新建/重开与多标签；IP/挑战验证仅辅助，不作为唯一保护。匿名公网前端不能证明动作来自真人，不能以“先做深蹲”当防刷。默认公网AI问答disabled，接口不向上游发请求、入口不启动该模式；纯运动和原明确备用战报照常可用。只有用户批准持久全局预算、金额上限与访问控制并通过并发测试后再考虑开放，不在本轮启用云资源。

## 分批实施与验收标准（本轮不开发）

A：先纯状态机与模拟接口测试：运动完成停计数；每人一题/答对再换人；HP0不发奖；全员答对才解锁；失败重置当前关且前关保留；跳过/休息/旧帧/旧结果不串人。保留旧纯运动分支。

B：本地真实百炼与恢复/账本：一次出题一次判题、私有参考答案、刷新/重复请求/服务重启恢复、uncertain与故障退出、额度扣减；少量真实调用需要用户确认测试额度。不用真实调用证明所有语义情况，测试夹具与真实结果分开记录。

C：界面/动画/真人验收后再评估公网，不把本地通过记为公网通过。不同时开发团队战报、线上联机、新摄像头模型。

自动测试必须覆盖：
- 2/6人、三关目标与最后一个问答的解锁门控；任何提前调用下一关均拒绝；题目输入/休息期间无计数。
- 达标最后一下只攻击一次；答对/失败只生效一次；HP0但未答对不触发胜利；换人/换关/重试旧响应不污染。
- 同回合并发出题、刷新、重启不重新发布；同提交重复判题缓存；不同输入同ID冲突；uncertain复判上限。
- 重试本关清当前关、保留前关/帽子/历史尝试；问答延后保留原题；全员跳过暂停。
- 同义短答、否定/矛盾、多解/错误参考答案、注入、畸形JSON、超长输入、异常反应；模型桩验证协议，真实语义测试另记录，不宣称绝对公平。
- 无Key、403/429/超时/断网/响应中断、磁盘与账本失败均不判负/不解锁；pending不自动再次付费。
- 预算在并发/重启/日切后不超应用设定硬上限；耗尽不调用；公网disabled即使有Key也零上游请求。
- 回归单人、三关纯运动、准备/计数隔离、AR、语音、声音开关、摄像头关闭/比例/隐私；类型检查与生产构建。

真人验收：两人逐关完成个人动作→走近答题→答对轮换；最后一人动作结束HP0时仍待答；最后答对才发徽章；验证一次错答本关失败及重开、uncertain和断网不判负、刷新保留同题/已有判定、休息和换帽无回归。不得要求过度运动，可用开发合成工具覆盖完整边界并与真人结果分别记录。不录制/上传视频或收集朋友身份。

三个关卡统一由levels.ts配置。史莱姆沿用原森林怪兽；幽灵使用迷雾场景与淡紫幽灵、闪隐抖动受击；巨龙使用城堡场景、翅膀/鳞片形象与后仰受击。各关共享同一计数与攻击流程，不复制识别算法。

第一关全员完成 → 本关胜利/徽章 → 主动点击“下一关 · 幽灵秘境” → 全队当前关0次、保持第一关历史 → 各人重新准备、依次完成3次 → 第二关胜利/徽章 → 主动进入巨龙城堡 → 各人4次 → 最终胜利页、三枚徽章与全队贡献。没有手动通关按钮，也不自动开始新关或新场。

2人整场为每人9次/团队18次；6人是每人9次/团队54次。这是配置推导，并已用合成姿态验证，不是新增真人测试数据。整场经过时间包含轮换与休息，仅在最终通关或提前退出后冻结，不做速度排名或健康收益推断。

## 实际代码变化与状态约束

- levels.ts：PARTY_LEVELS三关配置，FIRST_LEVEL保留为第一项别名。
- PartySession.ts：保存levelIndex、completedLevels、每位玩家三个关卡的counts；当前count与个人totalCount、团队teamTotal、HP和徽章均从记录推导，返回快照时复制历史数组。
- 新增levelWon状态表示前两关通关；won仅第三关全队达标。每个有效事件先验证当前active、attempt标识与单调repIndex，再入账和攻击；次数达到个人上限即停止。只在最后一人完成时发一次本关胜利事件，最终胜利事件仅发一次。
- nextLevel再次检查本关通关状态、全员实际达标、完成关数与索引；未完成或重复点击不推进。换关重置队列、当前关目标/尝试/基线/半次动作/跳过集合，历史、昵称和帽子保留。必须重新主动准备、识别和倒计时。
- 原队尾跳过/部分次数保留/全员跳过暂停不变；通关奖励页也可休息，继续后恢复奖励页而不是创建目标0的计数回合。提前退出保留已获奖励和真实贡献，明确未完成三关。
- PartyMonster.tsx：共享三种视觉形象/场景；PartyGame.tsx按当前配置显示关卡路径、个人/团队进度、HP与下一关；PartyFinal.tsx为本地确定性最终结算，不调用AI。
- 最终页显示每人2/3/4关记录、合计、贡献与帽子；贡献百分比四舍五入，原次数不修正。支持滚动、回看战场、Esc关闭和重新查看，冻结最终数据。

## 本地真人验收（请先用2人）

1. 打开 http://127.0.0.1:5173/ 并刷新，创建2人派对、填昵称和不同帽子，亲自开启摄像头/测试语音，进入战斗大屏。第一关初始40HP，两关均锁定；各2次后只到第一关胜利，获得萌芽伙伴徽章，不能提前进入后关。
2. 可先休息再继续，确认仍在奖励页；点击下一关进入幽灵秘境，初始60HP、每人0/3，第一关贡献仍保留，需重新准备。各3次后获得驱雾小队徽章，团队累计10次。
3. 主动进入巨龙城堡，初始80HP、每人0/4。各4次后出现最终胜利页，三枚徽章齐全。应为每人记录2/3/4、合计9次；团队18次，各50.0%。回看战场、额外站立/下蹲、再查看结算不应改变结果或时长。
4. 另开一场在第二关部分完成后休息/跳过，验证保留已完成次数；全员跳过仍暂停，不扣血。换人前下蹲未起立、换关后仅站直，均不能凭空加数；AR帽子、识别语音和攻击音应继续正常。提前退出保留已有徽章但不能显示最终三关胜利。
